# RoadRakshak — Control Room Demo: Developer Guide

This is the **showcase** build of RoadRakshak: a control-room UI driven by
recorded clips and hand-placed sample records. It runs without any AI, database
or backend, which is what makes it presentable from a laptop or from GitHub
Pages. The **working system** (ONNX detector, OCR, SQLite, Node API) lives in
a separate folder (`RoadRakshak/`) and is not covered here.

Two copies of the demo exist:

| Copy | Where | Serves | For |
|---|---|---|---|
| Source demo | `SIH/demo/` (this folder) | `python serve.py` → http://localhost:8090 | editing, local showing |
| Static site | `roadrakshak-demo/` (own git repo, branch `gh-pages`) | https://devloper-404.github.io/RoadRakshak-Repo/ | the live link |

Edit in `SIH/demo/`; `roadrakshak-demo/build_site.py` copies and patches it
into the static site. Never hand-edit the static copy — a rebuild overwrites it.

## 1. Files

### `SIH/demo/` (source)

| File | What it does |
|---|---|
| `index.html` | The whole dashboard: five pages and per-tab feature previews, all CSS and JS inline. No framework. |
| `challan.html` | Printable A4 e-challan. Opened by **Generate Challan** with the record in the query string. |
| `demo_data.json` | Cameras (id, place, clip, duration, when shot) and the violation catalogue (label, fine, MV Act section). Generated by `build_demo.py`, hand-editable after. |
| `journeys.json` | **GIS tab data**: camera coordinates, vehicles and their camera-to-camera hops. Hand-edited. |
| `journeys/` | Vehicle photos for the GIS tab + its README. |
| `violation/` | Violation stills. **The filename is the record** (plate, type, camera, vehicle). |
| `media/videos/cam01.mp4 … cam06.mp4` | The camera-wall clips, web-transcoded (H.264, 854 px wide, 20 fps, ≤ 26 s). Git-ignored in `SIH`. |
| `serve.py` | Tiny stdlib HTTP server. Adds `GET /api/violations` = live listing of `violation/`, and byte-range headers so video scrubbing works. |
| `build_demo.py` | One-time builder: transcodes raw phone footage from `SIH/data/input_videos/` into `media/videos/`, seeds `violation/` with stills, writes `demo_data.json`. |
| `README.md` | Short user-facing readme. |

### `roadrakshak-demo/` (static site)

Same `index.html` (patched), `challan.html`, `demo_data.json`, `journeys.json`,
`journeys/`, `violation/`, `media/videos/` — plus:

| File | What it does |
|---|---|
| `build_site.py` | Copies everything from `SIH/demo`, patches `index.html` (see §7), writes `violations.json`. |
| `violations.json` | Static replacement for `serve.py`'s `/api/violations` listing. |
| `.nojekyll` | Tells GitHub Pages to serve files as-is. |

## 2. How the pages work

All state is in memory on the page (`DATA`, `LOG`). Reload = reset.

**Camera Wall** — four `<video>` panels, muted/autoplay/loop, chosen from
`demo_data.json` cameras (`PANELS=[0,1,2,3]` = first four; each panel has a
dropdown to switch). The clock is real. No alerts on this page by design.

**Detections** — as a clip plays, each violation image scheduled on that camera
"fires" when the video reaches its `at` second (`wire()` watches `timeupdate`).
The latest capture shows big; earlier ones queue below. Firing repeats when the
clip loops (the `SEEN` set is cleared on loop).

**Violations** — every record in `LOG`, filterable by camera / type / status,
searchable by plate or place. Row click → evidence modal. **Re-enter plate**
edits the plate in place (marked "manually corrected"). **Generate Challan**
opens `challan.html`; the record becomes `CHALLAN GENERATED`. **Reject** →
`REJECTED`. Nothing is sent anywhere.

**Analytics** — counts, fine totals, worst location, bars by location and type,
computed from `LOG` each time the tab opens.

**GIS · Journey** — see §5.

## 3. Camera settings

`demo_data.json`:

```json
{ "id": "CAM-02", "location": "KP2 - Metro", "city": "Greater Noida",
  "video": "media/videos/cam02.mp4", "duration": 18.2,
  "source_video": "KP2_metro.MOV", "captured_at": "2026-08-17T10:54:37+05:30" }
```

| Field | Used for |
|---|---|
| `id` | Camera label everywhere; violation filenames and `journeys.json` refer to it |
| `location`, `city` | Panel header, records, challan |
| `video` | Clip path relative to `demo/`; **must be H.264** (`avc1`) or Linux/Chrome shows a black panel |
| `duration` | Seconds; used to spread violation `at` times across the clip |
| `source_video`, `captured_at` | Shown on the record and challan ("Source footage", "Clip recorded"); `captured_at + at` = "Offence at" |

The wall shows the first four cameras; add as many as you like, the dropdowns
list them all. The GIS tab keeps its **own** camera list (with coordinates) in
`journeys.json` — use the same ids so the two line up.

`build_demo.py` regenerates this file from its `CAMERAS` table
(`id, place, raw filename`) and `CITY`.

## 4. Adding or replacing a video

**Route A — raw phone footage through the builder**

1. Copy the `.MOV`/`.mp4` to `SIH/data/input_videos/`.
2. Add a row to `CAMERAS` in `build_demo.py`: `("CAM-07", "Alpha 1", "Alpha1.MOV")`.
3. `python demo/build_demo.py` — transcodes to `media/videos/cam07.mp4`
   (854 px wide, 20 fps, first 26 s, H.264 if the OpenCV build has it; if the
   result is not `avc1`, re-encode with ffmpeg: `ffmpeg -i in.MOV -vf scale=854:-2 -r 20 -t 26 -c:v libx264 -pix_fmt yuv420p -an cam07.mp4`).
4. It also writes the camera into `demo_data.json` (existing `violation/` images are left alone).

**Route B — already-encoded clip**

1. Put the H.264 mp4 in `demo/media/videos/`.
2. Add the camera object to `demo_data.json` (fields above).
3. Reload.

Limits for the live site: each file < 100 MB (GitHub hard limit), whole site
< 1 GB. `build_site.py` checks both and refuses non-H.264 clips.

## 5. Violation images (`violation/`)

```
<PLATE>__<VIOLATION>__<CAMERA>__<VEHICLE>.jpg
UP39T9319__OVER_SPEEDING__CAM-02__GOODS.jpg
UNKNOWN__WRONG_WAY__CAM-03__BIKE.jpg
```

| Segment | Values | If omitted |
|---|---|---|
| plate | `UP39T9319`; `UNKNOWN` = OCR failed → record goes to manual plate entry | filename used as the plate |
| violation | `NO_HELMET` `TRIPLE_RIDING` `WRONG_WAY` `OVER_SPEEDING` (keys from `demo_data.json` → `violations`) | cycles through the catalogue |
| camera | any id from `demo_data.json` | dealt round-robin |
| vehicle | `BIKE` `TW` `CAR` `AUTO` `GOODS` `TRUCK` `BUS` | inferred from the violation |

Rename a file → reload → the new plate flows through the feed, the table and
the challan. Timing: the first image on a camera fires at 18 % of the clip, the
second at 52 %, etc. (`schedule()` in `index.html`). Speeds for `OVER_SPEEDING`
are generated (78–123 km/h, limit 60). Fines and MV Act sections come from the
`violations` block of `demo_data.json` (`VIOLATIONS` in `build_demo.py`).

Only the vehicle ring and the label are burned into the stills by
`build_demo.py`; camera/location text is drawn by the page, so a renamed file
never contradicts its image.

## 6. GIS · Journey tab

Search a vehicle across cameras; see its route on a real map; open each
camera's footage at the moment it passed.

### Data: `journeys.json`

```json
{
  "cameras": [ { "id": "CAM-02", "name": "KP2 – Metro", "lat": 28.4632, "lng": 77.4948 } ],
  "vehicles": [
    { "plate": "UP16BX4521", "type": "Car", "colour": "White", "photo": "journeys/UP16BX4521.jpg",
      "hops": [
        { "camera": "CAM-02", "time": "2026-09-14T10:14:05+05:30", "video": "media/videos/cam02.mp4", "at": 6.5, "dwell": 4 },
        { "camera": "CAM-04", "time": "2026-09-14T10:14:58+05:30", "video": "media/videos/cam04.mp4", "at": 3.0 }
      ] }
  ]
}
```

| Field | Meaning |
|---|---|
| `cameras[].lat/lng` | Pin position. Current values are approximate spots around Knowledge Park II / Pari Chowk / Expo Mart — move them freely. |
| `vehicles[].photo` | Image shown in results and the journey card, path relative to `demo/`. |
| `hops[].camera` | Camera id (must exist in `cameras`). |
| `hops[].time` | ISO 8601 with offset. Hops are sorted by time; the route follows that order. |
| `hops[].video` | Clip to open for this sighting, relative to `demo/`. |
| `hops[].at` | Second in that clip where the vehicle appears — the player seeks here. |
| `hops[].dwell` | Seconds the "VEHICLE IN VIEW" ring stays on (default 5). |

### Behaviour

- **Search**: plate (full or partial, case/space-insensitive) · date · time from/to · camera. One match opens the journey directly; several list them; a date/time search without a plate lists every vehicle with a hop in that window and dims the hops outside it.
- **Recent vehicles** chips: one click per sample plate — handy on camera.
- **Map**: Leaflet 1.9.4 + OpenStreetMap tiles from CDN (needs internet). Pins = camera ids; on a journey they turn amber and get step numbers; the route is a dashed amber polyline. Clicking an idle pin lists who passed that camera; on a journey it opens that hop.
- **Timeline** (right): step, camera, time, gap from the previous camera, straight-line distance and the implied average speed (red above 60 km/h). Click a row → clip modal seeking to `at`, with Previous/Next camera.
- **▶ Replay journey**: walks the hops in order — marker slides along the route, each clip plays for `dwell + 2` s. Esc or Close stops it.
- **Offline**: if the Leaflet script cannot load, the same pins and route are drawn on an inline SVG schematic. Search and playback still work; only tiles are missing.

### Putting in real multi-camera footage

1. Copy the clips (H.264) to `demo/media/journey/` (or `media/videos/`).
2. Add each camera to `cameras` with a position.
3. Add the vehicle with one hop per clip; set `time` (fake is fine — it drives the order and the speed figure), `video`, and `at`.
4. Save a photo of the vehicle in `demo/journeys/` and point `photo` at it.
5. Reload locally; rebuild + push for the site (§7). `build_site.py` copies every clip referenced by a hop.

Tip: distances are straight-line between pins, so pick `time` gaps that give a believable km/h (0.5 km in 50 s ≈ 36 km/h).

### Per-tab feature previews

Each tab has its own short preview, shown over that tab (page blurred, 35 %
opacity) the first time the tab is opened. All in `index.html`: CSS under
"first-visit feature tour", markup `#tour`, JS "per-tab feature previews"
(`TOUR`, `TV`).

| Tab | Previews |
|---|---|
| Camera Wall | Camera Wall (+ "recorded footage and sample records" note) |
| Detections | Detections · How detections are made (pipeline) |
| Violations | Violation records · E-challan |
| Analytics | Analytics |
| GIS · Journey | GIS journey · Footage at every sighting / replay |

- **When**: on a tab's first opening per browser (`localStorage` key
  `rr_preview_seen_v2_<tab>`, set on Skip or Got it). The landing tab's shows on
  page load; the others when their nav button is clicked (`tourMaybe()` in the
  nav handler).
- **Again**: **ⓘ Preview** header button → current tab (`tourOpen()`);
  `?tour` in the URL → every tab once more for that visit.
- **Controls**: Next → / Got it, Skip preview; dots + "N / M · N more" only when
  a tab has more than one preview; keys → ← Esc.
- **Editing**: each `TOUR` entry has `tab` (`cams`, `det`, `vio`, `ana`, `gis`),
  `vis` (key into `TV`, the illustration), `tag`, `title`, `text`, optional
  `fine`, `pts`. Entries are grouped by `tab` in array order. To show changed
  previews to everyone again, bump the key to `rr_preview_seen_v3_`.

## 7. Publishing to GitHub Pages

```bash
cd ~/SIH/roadrakshak-demo
python build_site.py         # copy + patch from ../SIH/demo, checks codecs and sizes
git add -A && git commit -m "update demo"
git push site gh-pages       # remote 'site' = DEVloper-404/RoadRakshak-Repo
```

The page is live ~1 minute later at https://devloper-404.github.io/RoadRakshak-Repo/
(hard-refresh if you see the old one). If Pages ever stops: repo → Settings →
Pages → Branch `gh-pages` / `(root)`.

What `build_site.py` changes in `index.html` (and nothing else):

- `fetch('api/violations')` → `fetch('violations.json')` (no server on Pages);
- the two "run build_demo.py" status messages → neutral text;
- adds the "Demo · recorded footage · sample records" note on the Camera Wall.

If you rename either of those strings in the source, update `PATCHES` in
`build_site.py` — it stops with a clear error rather than publish a broken page.

Pages cannot do byte-range requests reliably, so seeking in videos is a little
less smooth there than locally; playback is unaffected.

## 8. Running locally

```bash
cd ~/SIH
.venv/bin/python demo/serve.py            # opens http://localhost:8090
.venv/bin/python demo/serve.py --port 9000 --no-browser
```

Any static server also works for everything except the live folder listing
(`python -m http.server` → violations appear only if `violations.json` exists,
i.e. in the static copy).

Browser notes: videos are muted so autoplay is allowed; the demo pauses feeds
when the tab is hidden and resumes on focus (`keepPlaying()`); the clock and
"Detected" timestamps are the machine's local time.

---

## 9. Things that are deliberately fake here

Plates, violations, times and journeys are sample data; the "AI · 15 FPS" HUD
and confidence values are decorative. Seatbelt detection was removed from the
demo because it could not be judged reliably through a windshield. The real
detection pipeline, database and API are in the `RoadRakshak/` project.
